# Git

Для папки, которая хранится в Git:

- Файлы, изменённые после последнего коммита, отмечены на боковой панели: **M** изменён, **A** добавлен, **U** новый и ещё не в Git, **R** переименован, **!** конфликт.
- В изменённом документе у каждого абзаца, заголовка или списка со строками, которых не было в последнем коммите (по сохранённому файлу), есть отметка на правом поле; щелчок по ней делает коммит (Textus 1.4.4).
- Строка состояния показывает ветку, а также ↑ коммиты к отправке и ↓ коммиты к получению; щелчок по ней делает коммит.
- **Закоммитить изменения…** (меню «Плагины» или щелчок по ветке) показывает список изменённых файлов, где уже выбран файл на переднем плане; вы пишете сообщение, и ваш собственный Git коммитит только эти файлы — хуки и подпись работают как обычно. Перед первым коммитом в папке плагин сначала спросит.
- **Отправить (push)** и **Получить (pull)** (меню «Плагины») отправляют ветку в её удалённую ветку и забирают коммиты из удалённого репозитория — вашим собственным Git и с сохранёнными в нём учётными данными; если он попросит, один раз войдите через Git в терминале. Ветка, у которой ещё нет удалённой ветки, отправляется в `origin`. Получение, которое привело бы к конфликту, отменяется, ничего не меняется, и вам об этом сообщают (Textus 1.4.6).
- С Историей версий 0.4 коммиты документа показываются среди его версий, и их можно так же сравнивать и восстанавливать.
- Textus AI может читать изменения, коммиты файла и файл таким, каким он был в коммите, — например, чтобы набросать сообщение коммита.

Ветки плагин никогда не переключает. Нужны установленный Git (на Mac — Command Line Tools) и Textus 1.4.6.

## Инструменты для Textus AI

Когда плагин установлен, Textus AI может пользоваться ими в разговоре:

- `git_changes`: Ветка открытой папки и изменённые файлы, для каждого изменённого текстового файла — строки относительно последнего коммита. Прочтите перед тем, как писать сообщение коммита.
- `git_history`: Коммиты Git для файла, от новых к старым, с учётом переименований: хеш, дата, автор, тема.
- `git_file_at`: Текст файла, каким он был в одном из коммитов (хеш из git_history).
